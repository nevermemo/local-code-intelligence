# Engineering roadmap and backlog

This file is the source of truth for ongoing LCI improvement work. It is written
for an implementer who has not read any prior conversation: every item is a
bounded slice with its own evidence, scope, acceptance criteria, and
dependencies. It survives context compactions; the research that produced it is
not committed, so the evidence each item needs is restated here with URLs.

## How to use this file

1. Pick the top `ready` item in the lowest-numbered priority tier whose
   dependencies are `done`. Do not skip tiers for convenience; P0 exists because
   later items cannot be judged without it.
2. One item = one slice = one commit (plus the regular `cargo xtask test --suite
   Full` gate). Split an item rather than letting a commit grow past it.
3. Before starting, load the matching project skill (`.agents/skills/lci-*`):
   ranking/latency work uses `lci-retrieval-evaluation`; LSP work uses
   `lci-lsp-adapter`; grammar/extension work uses `lci-language-adapter`.
4. Ranking, fusion, reranker, document-format, instruction, and candidate-count
   changes need a before/after evaluation (the retrieval contract requires it):
   run `evaluate ./evaluations/core.toml --workspace self=$PWD` and
   `evaluate ./evaluations/mined/self.toml --workspace self=$PWD` before and
   after (frozen binaries, `compare` or `--baseline` for the CI), keep the JSON
   under `test-results/` (never committed), and put the headline numbers
   (hit@1, hit@3, MRR, nDCG@10, p50 total and p50 reranking, CI of the delta)
   in the commit message and in this file's item entry.
5. Update this file in the same commit as the work: move the item to the Done
   table with its commit hash, set a successor's status to `ready` if its
   dependency was the only blocker, and append newly discovered work as new IDs.
   Never renumber or reuse IDs.
6. Anything that downloads model weights needs the owner's explicit approval
   first (state model, source, size). Anything that would add Docker, a web UI,
   another database, another service, or contact port 8765 is out of bounds
   (AGENTS.md "Hard rules") and belongs in the parking lot, not the backlog.

Status legend: `done` (hash in Done table) | `partly done: <what remains>` |
`in-progress` (uncommitted or another agent) | `ready` (deps met, can start
now) | `blocked(reason)` | `needs-approval(what)` | `research` (produces a
decision, not a feature) | `dropped(reason)`. The table row is the only home of
an item's status: an item's header line carries `status: see table`, then size,
dependencies and skill (older headers that still show a status word are fixed
when touched; where header and row disagree, the row wins).

Size: S = under half a day, M = about a day, L = more than a day (must be split
before it is picked).

Naming: a new item takes the next free ID in its letter series; look for the
letter in the whole file (every tier table and every `###` heading -- the A
series, for example, has A1-A4 in the P2 table and A5-A6 in the P3 table).
A slice of an item is the item ID plus a lowercase letter (A6a, A6b; N3a,
N3b); a slice is never a new ID. Tier names (P0, P1, P2, P3) name priority
tiers only and are never used as slice names (the slices first planned as
P1a, P1b, P2a and P2b are A6a, A6b, N3a and N3b; commit messages written
before this rule still use the old names). A document's internal numbering
(pre-registration amendments, audit actions) is scoped to that document; none
of it is a roadmap ID.

## Strategy checkpoint (2026-10-11)

- **Sanity check.** A next-generation design run (the "LCI map": one code graph with precise edges, vectors on nodes, docs, history and agent cards; notes untracked under `research_notes/grand-vision/`) was paused after an independent review with no stake in it (`research_notes/grand-vision/sanity-check.md`). Findings: the premise that richer retrieval makes coding agents better has never been measured (I-10); the retrieval sets no longer discriminate designs (the gold file is already in the top-24 pool for 44 of 46 queries, on one 92-file repository that ripgrep scans in 0.15 s); the run's own pre-registered spikes falsified its strong synergy claims (tag edges, cards as reranker input, semantic hops, co-change weighting, neighbour injection, an embedder-free fast mode), and what survived (stable symbol identity, per-file derivation in 12-19 ms) is infrastructure that resembles existing systems; volume ideation with model-assigned scores produced little that measurement did not.
- **Decision (owner).** Run I-10 first, as an agent A/B: 15 public repositories of varied size, shape and language, 20 generated content repositories (txt, md, json, yaml, png, pdf, ...), and the 45 replayed-commit tasks of this repository; arms native tools only / plus language-server navigation / plus LCI fast / plus LCI deep, with the native tools present in every arm; decision rules pre-registered before any run. Further map work happens only where the A/B shows LCI helps.
- **A/B plumbing in LCI (infrastructure only, nothing measured changes).** AB-1 (2026-10-11): `LCI_CANDIDATE_DUMP=<file>` makes a process append each search's whole fused pool (the E0 trace) as one JSON line, responses unchanged, fail-open; the pool gives the A/B's training-ready logs their hard negatives. Landed since: search profiles in config and on the CLI (A6a `15bc4c6`; per-connection use over MCP and REST is A6b, which lets one `serve` offer the fast/deep arms over one shared index and language-server set) and idle language-server release (N3a `ced5fbf`). Next: A6b and N3b (REST release endpoint, release on Ctrl+C).
- **Working principle (owner).** Measurements guide opinions and opinions guide measurements: measure a premise before designing on it, prefer small falsification tests to idea volume, and run sanity checks at phase boundaries (`.agents/skills/lci-autonomous-improvement/SKILL.md`, "Measure, decide, sanity-check").

Done 2026-10-11: GO WITH FIXES (`research_notes/grand-vision/ab/SC1.md`): blockers one-server layout (pre-registration A23) and configuration provenance (serve ignores local overlays and refuses inherited `LCI_*`; the freeze records `lci config` per config); ten should-fix items adopted in A24 (M7, index-reuse proof, canary re-run, embedder noise stated and counted, tool-usage rate, two sensitivities, Bash-rule record, memory check, dependency limitation); no threshold moved.

  - SC5 -- before pre-registering phase 2 (cross-map verbs and interfaces) and before any training or distillation on the RTX 5090.
  - SC6 -- after A7's implementation and docs are in place (A7a-A7e landed): does the result keep agents in the decided flow? Measured first: a fresh agent in a clean worktree with no local files, and one on the owner's machine, each given tasks that need a path, port or URL, must find or create every value through the documented resolvers without guessing; then the review (neutrality evidence, docs consistency, nothing machine-specific committed). - **Long-range map (a decision tree, not a fixed plan).** Each branch starts with a pre-registered measurement and ends at a sanity checkpoint:
  1. A/B (I-10) STOP -- LCI does not cut agent calls/tokens or raise success: narrow LCI to a fast default (fusion-only), navigation ergonomics (compact results, symbol addressing, call hierarchy) and robustness; shelve the map; test push-style help (post-edit impact hints via client hooks) as the next cheap premise.

CONTINUE overall or in a stratum (e.g. large repositories, descriptive tasks): focus LCI there; phase 2 measures maps and interfaces on the gold families (flow, impact, history, instructions, regression localisation): explicit cross-map verbs, one bundle verb, a query or code-mode interface, and push hooks, each against native tools plus git and a language server; build only the winners.
  3. INCONCLUSIVE: extend tasks (up to 20 per repository) before deciding.
  4. Only where retrieval quality is shown to change agent outcomes: models on the RTX 5090 -- fine-tune and distill the embedder/reranker on agent-use labels (the A/B's training-ready logs; evaluation repositories stay evaluation-only), then, if justified, a small navigation policy trained on commit-replay rewards; a long-context baseline is spiked first as the honest competitor.

## Parking lot (ideas kept out until the owner changes the product boundary)

| Idea | Why parked |
| --- | --- |
| LLM-generated chunk/file summaries and wikis (DeepWiki, CodeWiki, kit's docstring index) | Needs a generation model; the only one available is on port 8765, which LCI must never contact. The boundary-respecting variant is A5's `annotate` tool that stores summaries the calling agent already wrote, keyed by chunk hash. |
| Server databases or search engines (Qdrant, Milvus, Meilisearch, Typesense, Elasticsearch, Memgraph/Neo4j) | AGENTS.md forbids another database or service; LanceDB already has FTS, `merge_insert`, `optimize`, scalar indexes. |
| Embedded second database for the manifest (SQLite, redb) | Arguably "another database"; try LanceDB-native and JSON improvements (W1) first; revisit only if the manifest becomes a measured bottleneck. |
| Web UI, system tray, graph explorer | Web frontend is excluded; a tray app is new product surface. |
| Docker packaging | Excluded by AGENTS.md. |
| Symbolic editing (rename, replace body) | Conflicts with the retrieval focus; documented duplicate-code failure mode (https://github.com/oraios/serena/issues/576). An LSP `rename` preview that returns a WorkspaceEdit without applying it could be revisited. |
| Custom trigram/suffix-array index (Zoekt, livegrep style) | Premature below monorepo scale; `rg` scans this repo in 0.15 s. |
| stack-graphs, Kuzu, CozoDB | Archived or dormant upstreams. |
| Non-commercial models and code (jina-reranker-v3/v3.5, recent Jina embeddings, GitNexus, jCodeMunch) | Licensing blocks redistribution or reuse. |
| In-process fallback embedder (fastembed-rs ONNX, model2vec `potion-code-16M-v2`) | Needs model download approval plus ONNX runtime packaging and a second vector column; quality is far below Qwen3-4B (CoIR 39 vs ~60 for CodeRankEmbed). Revisit after M3 if a service-less mode is wanted. |
| LLM query rewriting / HyDE inside LCI | Would need a generation model and demonstrably drops anchors (CORE-Bench); the calling agent can rewrite its own queries. |
