Reading (rules 2, 3, 6):

  in every band, and on file F1 in every band: every paired interval excludes 0. The gap is
  largest on the `unique` band (0.183 against 0.995), where the baseline is near its ceiling, and

## 5. Pre-registered expectations (section 6 of the pre-registration)

* `impact`: below `grep_baseline` on `decl_f1` in every band, most clearly on `unique`; file
  recall decent and file precision low. **Held** (0.790 file recall; 0.226 file precision).
* `where-to`: `reg_hit@3` within a few items of BM25; set metrics near zero. **Held** for
  registration (equal) and for exemplar; on convention BM25 is higher (0.253 against 0.010).
* `flow`: higher on `named` than `descriptive` and on flagged than not flagged; headline below
  0.5. **Held** (0.199 / 0.023, 0.239 / 0.068, 0.104).

## 6. What can and cannot be said

* [M] A lexical-only LCI over the frozen tree, with defaults, recovers the right files for
  `impact` questions (recall 0.79) but not the right declarations (recall 0.35, precision 0.11),
  and `grep_baseline` is far ahead on every band.
* [M] On the headline `flow` items it names about 10% of the gold intermediates and no complete
  path; what it finds depends on words shared with the endpoints.
* [M] On `where-to` registration items it equals a file-level BM25 in the top 3.
* [I] The lexical channel returns chunk-sized matches of the question's words; that explains
  the file-high, declaration-low pattern, but no run here separates ranking from chunking
  beyond the span-overlap diagnostic.
* [G] A semantic channel and a reranker (M0b) are the natural candidates for the `descriptive`
  items; nothing here measures them.
* Nothing here is a gate; the numbers are the baseline against which M0b and later arms are read.

## 7. Deviations and disclosure

* **The `where-to` gold.** The pre-registration named hash `81aa1cd3...` (60 items) and expected a
  provisional gold. The gold was revised twice while this slice ran and was accepted (its section
  12.12); the run used `5f0f0e7f...` (59 items, 0056 dropped), recorded in section 1, and labelled
  accepted. The run on that file is the only `where-to` run.
* **No mechanics smoke test** was run on a toy directory (the pre-registration allowed one). The
  first query of `impact` created the index. The build was the only preparation.
* **Build.** The first release-build attempts failed in the shell sandbox (a missing `protoc`
  and an `sccache` socket error). The build was repeated from the PowerShell tool with `PROTOC`
  pointing at the tool copy inside the worktree, the default target directory of the worktree and
  `sccache` left on. No source change.
* **Post-hoc diagnostic.** The span-overlap recall of section 2 was added after seeing the
  `impact` result, to separate the C1 loss from ranking. It is labelled as such and is not part
  of the pre-registered reading. The full-path share for `flow` is pre-registered.
* **Analysis script fixes before results were read.** The per-item script first crashed on
  metrics undefined for an item and was fixed to skip them; its consistency check was changed to
  skip metrics the scorer reports as `null`. Neither affects a number.
* **`lci evaluate` exits 1** when expected paths are missing (8, 8 and 23 queries of the three
  sets); the reports were complete and the answers were taken from them. The expected paths are
  not used by the scorers.
* **Wilson versus bootstrap.** The rule was applied mechanically: a metric whose per-item values
  are all 0 or 1 in a cell uses Wilson, so some small-cell recall@k values and the all-zero
  BM25 declaration metrics (not read) carry Wilson intervals.
* **`flow` BM25 and grep arms** do not exist (section 3 of the pre-registration).
* Nothing else differs from the pre-registration. No setting was changed after the first run.

Scripts, the stub, the configuration and raw reports stay in the scratch directory.
