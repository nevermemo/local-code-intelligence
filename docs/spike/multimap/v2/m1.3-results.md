# M1.3 results: the compiler probe (L5) against the M0.5 mutations

Pre-registration: `m1.3-prereg.md` (sections 1 to 9 and amendment 1), committed before the code
(`compile_probe` example and `lci-maps::probe` module). One full run, 2026-10-14, after one aborted
first attempt (section 6). No model was called. Labels [M] measured, [I] inferred, [G] guess. This is a
plumbing-equality and wall-time measurement on one tree, not an agent result. All timings are marked
**under load, quiet re-run owed** (prereg section 6); the load actually observed was low (section 4).

## 1. Verdict

| question | result [M] |
| --- | --- |
| Equal to M0.5 (match = E1 and E2 and same build outcome and same `external_spans_skipped`) | **20 of 20** [Wilson 95%: 0.839, 1.000]. E1 (site set) 20/20; E2 (NodeId set plus count of unattributed sites) 20/20. |
| Descriptive: same blocked-unit set / same error code counts / same site set over the three warm repetitions | 20/20 / 20/20 / 20/20 |
| Totals | 221 sites over the 20 mutations, 27 of them unattributed (`use` lines): the gold's totals. All 20 mutations fail to build, as in M0.5. `external_spans_skipped` 0 throughout. |
| Warm `cargo check` wall, r1 (n 20, the M0.5-comparable repetition) | p50 4.20 s [3.98, 4.64], p95 6.95 s [5.04, 8.97]; M0.5 gold: 4.31 / 6.33 s. |
| Warm, all three repetitions (n 60) | p50 4.14 s [3.91, 4.56], p95 6.92 s [5.20, 8.66]. |
| Cold-workspace (n 20) | p50 12.5 s, p95 16.7 s (intervals in section 3). |
| Cold-full, unmutated (n 1) | 660.7 s (M0.5: 561 s). |

Reading: the probe, rebuilt as a product-shaped tool (patch file in, `compile_error_at` edges out), loses
nothing against the M0.5 one-off script on these mutations. This tests the probe's plumbing (patch
handling, parsing, de-duplication, mapping), not the correctness of the oracle, and E2's mapper reads
the same SCIP index as the gold's mapper (same-oracle circularity [I], prereg section 8). The 20 mutations
all break the build, so there is no no-break class.

## 3. Timing [M]

Wall clock around the `cargo check` process only (`cargo check --workspace --all-targets --keep-going
--message-format=json`); intervals are percentile bootstraps over mutations (10,000 resamples, seed
20261014); percentiles by linear interpolation. The p95 of 20 or 60 values is an unstable estimate.

| series | n | p50 | p95 | min / max |
| --- | --- | --- | --- | --- |
| warm, r1 (m01..m20) | 20 | 4.20 s [3.98, 4.64] | 6.95 s [5.04, 8.97] | 2.75 / 8.97 |
| warm, r2 (m20..m01) | 20 | 4.09 s | 5.88 s | |
| warm, r3 (m01..m20) | 20 | 4.19 s | 6.32 s | |
| warm, all | 60 | 4.14 s [3.91, 4.56] | 6.92 s [5.20, 8.66] | 2.64 / 8.97 |
| cold-workspace | 20 | 12.5 s [6.93, 12.84] | 16.7 s [15.29, 17.44] | 6.27 / 17.44 |
| cold-full, unmutated | 1 | 660.7 s | | |

Warm by kind (all repetitions, n 15 each), p50 [min, max]: rename 5.76 s [3.92, 8.97]; arity 4.32 s
[3.20, 4.75]; field removal 3.87 s [3.75, 4.58]; visibility 3.58 s [2.64, 5.37]. The same ordering as
M0.5 (rename slowest, visibility fastest). Cold-workspace by kind has n 5 per kind (too small to read);
its field-removal samples are all 6.6 to 6.9 s and the other kinds 6.3 to 17.4 s. The cold-workspace
samples are bimodal [I]: mutations whose errors are inside `lci-core` itself abort the dependents early (about 6.5 s), errors in the root
crate cost a full re-check of `lci-core` first (12 to 17 s).

* Per-kind p95 and bootstrap intervals (prereg section 5, "and per kind") were dropped: a kind has 5 mutations, so n 15 in the warm series (5 mutations x 3 repetitions, not independent) and n 5 in the cold-workspace series, too few for a p95; only p50, min and max are given per kind. The results come from a code version that includes the review fixes made after the run (workspace-path test without a directory list, `git clean -fd` in the restore and a cleanliness check that counts untracked files, a documented one-level expansion rule, a char-safe path prefix strip, a dead assignment removed). None of them changes a reported number: the first cannot change `external_spans_skipped` (0 here), and the second affects only files a patch adds, of which these mutations have none.
* Median ratio of the r1 warm time to the gold's time for the same mutation: 0.94 [M]. The p95 is higher
  than the gold's (6.95 against 6.33 s) and the p50 slightly lower; the differences are inside the bootstrap
  intervals and no regression is claimed.
* Rest of one probe call, p50 (r1): patch apply 38 ms, restore 58 ms, parse and map 41 ms. The SCIP load
  (544 ms, debug build) is paid once per process and is outside the timed span; a resident probe would
  not pay it per call. The untimed re-warm check after each restore: p50 4.61 s (M0.5: 4.98 s).
* Definitions as pre-registered. Warm: target dir holds a completed check of the unmutated tree; after
  each probe the tree is restored and a re-warm check must pass with 0 errors (it did, 60 of 60).
  Cold-workspace: `cargo clean -p` for every workspace package (the clean is outside the timed span; the
  fingerprints of the workspace crates were confirmed removed before each of the 20 samples), then the
  patch and one check, dependencies kept. After the 20th sample the unmutated tree needed 12.7 s to
  re-check cold-workspace (n 1, not timed as a series). Cold-full: empty target dir, unmutated tree, once.
* The 561 s of M0.5 and the 660.7 s here differ by 18%; M0.5 had a busy-loop of one core during its
  run, this run had none (cold-full started with total CPU at 2%). Both are n 1; the difference is not
  explained [I: other tenants of the 24-core machine, background processes].

## 4. Load lines [M]

Each timed series has a "before" and an "after" line; every probe call also records the running `cargo`,
`rustc` and `lci*` processes just before it starts. In every line the only matching process was the A/B
runner (`lci-ab`), and total CPU was 0 to 2%. Before 3 of the 60 warm calls another `cargo` process was
running (m16 in r1, m05 in r2, m20 in r3, two `cargo` processes each); their times (r1 m16, r2 m05, r3
m20) are in the series above and were not excluded. No cold-workspace call and no cold-full run saw one.
By the prereg labelling rule a series is "contended" if another cargo or rustc ran at either end: none
was. The tag "under load, quiet re-run owed" stays as pre-registered, but the observed CPU load was
close to zero, so a quiet re-run is expected to change little [G].

client waits for, on the first probe in a fresh worktree that shares a target dir. A fresh target dir
(660.7 s) would need the background path.

## 6. Deviations and disclosure

* **First attempt aborted.** The first warm series stopped at m11: the probe's revert (`git apply -R`)
  left the tree not clean for a pure line deletion in a CRLF checkout (the restored line has LF line
  ending), so the probe exited with a failure and the harness stopped. The tree was restored, the revert
  was changed to `git checkout -- .` (as the M0.5 runner did; prereg section 3 said `git apply -R`; this is
  a deviation of the probe's implementation, not of a measured quantity), the outputs of that attempt were
  kept aside, and the warm series was run again from the start. In the aborted attempt m01..m10 ran
  before the failure; its one anomaly, m01 at 18.3 s as the first call after the cold-full build (the
  final run's m01 at the same rank: 6.8 s), is not in any number above and is not explained [I: first
  call after a large cold build, cold file cache]. That attempt's other timings were similar to the final
  ones. The cold-full run was made before the revert change and is unaffected by it (no patch).
* My analysis script ran once, for a few seconds on one core, while the first cold-workspace sample was
  in progress; that sample (m01, 16.6 s) is included.
* Cold-full is the unmutated baseline only (amendment 1).
* The probe was built in the dev profile (unoptimised); this affects the SCIP load and mapping times
  only, not the timed cargo span.
* The mutation diffs were exported from the private gold by a throwaway script to patch files outside
  the repository; the harness and the comparison script are scratch files, not committed. This document
  carries mutation ids and aggregates only; the per-mutation site lists, seed names, paths and diffs
  are in the private gold and in the scratch outputs.
* Hashes recorded at run start: tree commit `bfaff446316636e2089e0440bfcf127394950c42` (as pre-registered);
  gold `<gold>/mutation.json` sha256 `24ea332b54511aebf81cb620c8c14c61db8e279f33b062a9161a7fdb5e9d6e3a`;
  SCIP index sha256 `81b83d2eb3a2c1777fca4032b99633cf747fcaa883cb934cf89390dc3b0b421a` (the index of M0.4 and
  M1.4); rustc and cargo 1.98.0.

## 7. What this changes

Nothing is a gate. The probe can be used as the exact `compile_error_at` source for M1.4's
`why(error)`/`impact` verbs: it reproduces M0.5 exactly, and its warm cost per patch is about 4 s.
The M0.5 findings stay as they were: an import error masks its consumers, visibility reductions are
reported at `use` lines (25 of the 27 unattributed sites), and a failing target blocks its dependents,
so the edge list is a subset of the real consequences and must carry its blocked units. Open: quiet
re-run of the timings; a no-break control; a probe on the current head (not the frozen commit).

## 8. Reproduction

```text
<scratch>: detached worktree of the frozen commit, protoc in .tools/, own CARGO_TARGET_DIR
cargo build -p lci-maps --example compile_probe            # unit tests: cargo test -p lci-maps --lib probe
compile_probe --tree <tree> --target-dir <dir> --out <out.json> [--patch <file>] [--patch-id <id>] [--scip <index>]
```

Series order: cold-full (empty target dir), warm r1, r2, r3 (apply, probe, restore, re-warm), then
cold-workspace (`cargo clean -p` of all workspace packages before each sample). Harness, comparison
script, patch files and raw outputs live in the scratch directory and are not part of the repository.
