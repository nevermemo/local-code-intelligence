# M1.3 pre-registration: the compiler probe (L5) against the M0.5 mutations

Slice M1.3 of the multimap spike v2 (brief row M1.3: "apply a patch in a scratch worktree, run
`cargo check`, map the spans to NodeIds, returned as `compile_error_at` edges; warm and cold wall
time; done when p50/p95 are measured and the result equals M0.5 on the same mutations"). No model is
called. Written before any code or run; the commit that adds this file precedes the code and any
result. Results go to `docs/spike/multimap/v2/m1.3-results.md`.

Labels: [M] measured, [I] inferred, [G] guess. Nothing here is a gate (the MVP has no viability
gates); the numbers order the work and describe the probe.

## 1. Question

Fixed before any run: **does a reusable probe (patch file in, `compile_error_at` edges out) reproduce
the compiler oracle of M0.5 exactly on the same 20 mutations, and how long does it take warm and
cold?** M0.5 was a one-off script run; this slice rebuilds it as the product-shaped tool and checks
that nothing was lost. It is not an agent result and says nothing about usefulness to an agent.

## 2. Frozen inputs

| input | identity |
| --- | --- |
| Tree | `<tree>`: a detached scratch worktree of commit `bfaff446316636e2089e0440bfcf127394950c42` (the M0.5 tree, not the current head), made under `<scratch>/m1.3/`. Its own `CARGO_TARGET_DIR` under `<scratch>/m1.3/`; `PROTOC` from the copied `.tools/`. |
| Toolchain | cargo/rustc 1.98.0, Windows host, default features. A different version is recorded and flagged; the equality reading then carries that caveat. |

| Reference | the gold's per-mutation `error_sites` (code, file, line, column, innermost declaration or unattributed class), `blocked_units`, `external_spans_skipped`, break label (all 20 break), wall times. |

If the commit, the gold file hash or the index hash differs at run start, the run stops.

## 3. The probe

`lci-maps` example `compile_probe` (one mode, `probe`): inputs `--tree`, `--patch`, `--scip`,
`--target-dir`; steps: verify the tree is clean, `git apply` the patch, run the **same oracle command
as M0.5**, `cargo check --workspace --all-targets --keep-going --message-format=json`, revert the
patch (`git apply -R`), verify the tree is clean again, parse, map, and write the edge list.
Re-warming after the revert is the harness's job, not the probe's, and is untimed here.

**Parsing and de-duplication** (as M0.5): primary spans of level-error messages; a span from a macro
expansion is replaced by its expansion site if that is inside the workspace, else skipped and counted
(`external_spans_skipped`); key `(code, file, line, column)`, first occurrence kept, de-duplicated across units.

**NodeId mapping rule.** A site's NodeId is the SCIP symbol of the innermost unit whose enclosing
range holds the 0-based (line, column) of the span start, using `ImpactIndex::unit_at` of
`lci-maps::impact` (the M1.4 definitions and ranges, with the enclosing-range repair); units are the
function, method, type, constant and static kinds of M1.4. A site with no unit is **unattributed**
(in M0.5 all 27 were `use` lines) and is kept as the site node `(file, line, column)`. Rustc columns
(characters) are used as SCIP columns without conversion, as in M0.5; a site on a line with
non-ASCII text before the span is listed. Each site gives one edge `compile_error_at(patch, node)`
with the code, message and position.

## 4. What "equal to M0.5" means

Evaluated per mutation, on the first warm repetition, and not tuned afterwards:

* **E1 (site set):** the probe's de-duplicated set of `(code, file, line, column)` equals the
  gold's set exactly (same size, same members). E1 does not depend on the SCIP mapping.
* **E2 (NodeId set):** the set of NodeIds of attributed sites, plus the count of unattributed sites,
  equals the gold's (its declaration symbols are compared as SCIP symbol strings; the gold's mapper
  is the Python `Graph.enclosing` over the same index, the probe's is the Rust `unit_at`).
* **Match = E1 and E2 and equal build outcome (all 20 fail) and equal `external_spans_skipped`.**
* Descriptive, not part of the match: equality of the blocked-unit set, and of the error code counts.

The headline is the number of matching mutations out of 20, with the list of non-matching ids and,
for each, the first difference. Wilson 95% interval printed. A mismatch that traces to a mapper
difference (E1 holds, E2 fails) is reported as that and not adjusted away. Determinism: the three
warm repetitions of a mutation must give identical site sets, or the run is flagged.

## 5. Timing

Wall clock around the `cargo check` process only (comparable to the M0.5 numbers); patch apply,
revert, parse and mapping are timed separately and reported as the rest of the probe call. The
SCIP load is one-off (reported once, not per call).

* **Warm.** The target dir holds a completed check of the unmutated tree (a cold unmutated check
  first, untimed here), and after each mutation the revert is followed by a re-warm check that must
  succeed with 0 errors (else the run is invalid for that mutation). Each of the 20 mutations is run
  **3 times** in rotating order (r1: m01..m20, r2: m20..m01, r3: m01..m20 again); n = 60 samples, of
  which r1 (n 20) is the one directly comparable to M0.5. p50 and p95 by linear interpolation
  (M0.5's method) over the 60 and over r1, with a percentile bootstrap interval for each (10,000
  resamples over mutations, seed 20261014), and per kind. The repetitions of one mutation are not
  independent; p95 at n 60 is still an unstable estimate and is labelled so.
* **Cold, two definitions, both stated:**
  * **Cold-full:** a fresh empty target dir (all dependencies rebuilt), the mutation applied, one
    `cargo check`. n = 3 (m01 xtask, m04 lci-core, m17 root lib, chosen now for covering three
    failing crates), plus the unmutated baseline once. No p95 (n too small): each value is printed.
    A failing mutation aborts dependents, so cold-full is cheaper than the unmutated baseline.
  * **Cold-workspace:** `cargo clean -p` for every workspace package, then the mutation applied and
    one `cargo check`, dependencies' artifacts kept (this is what a probe pays for a fresh scratch
    worktree sharing a target dir). n = 20 (every mutation once); p50/p95 as above.

## 6. Load note

An A/B batch runs on this machine for hours, so **every timing is taken under load** and is labelled
"under load, quiet re-run owed". M0.5's own numbers had unmeasured load too. Before each timed series
(each warm repetition, the cold-workspace series, each cold-full run) the harness records a load line:
total CPU percentage, and the count and names of running `cargo`, `rustc` and `lci` processes, and again
after the series; a series where another `cargo` or `rustc` process was running at either point is
marked "contended". Absolute times are not compared with a threshold; the ratio to M0.5 is
described, with the load lines beside it. The harness itself uses no polling loop.

## 7. Expectations (guesses, fixed before the run)

| item | expectation [G] | if it fails |
| --- | --- | --- |
| E1 match | 20/20 (same tree, command, toolchain, deterministic compiler) | below 18/20: the probe differs from M0.5; stop, find the difference (toolchain, tree, dedup, patch), rerun unchanged; the first attempt stays in the record. Not a tuning loop |
| E2 match | 19/20 or 20/20 (mapper rewritten in Rust) | a mapper difference is reported with its cause |
| 20/20 fail to build | yes | any pass: the patch did not apply as in M0.5; investigate before any other reading |
| warm p50 / p95 | 3 to 8 s / 5 to 12 s (M0.5: 4.3 / 6.3 s), higher under load | reported; reading rows below |
| cold-workspace p50 | 60 to 200 s | reported |
| cold-full | 500 to 900 s for an unmutated build (M0.5: 561 s); mutated runs lower | reported |

Reading of the warm p95 (descriptive; no gate): up to 10 s, interactive-class; 10 to 30 s, usable as a
tool call that the client waits for; above 30 s, the probe would run in the background. Cold figures
describe first use in a new worktree only.

Invalid run (stop, fix, rerun unchanged): the tree is not clean after a revert; a re-warm check
fails; a hash of section 2 differs; a mutation's three repetitions give different site sets (flagged
first, invalid only if the cause is the harness).

## 8. Validity and limits

* The oracle is the same command as M0.5, so equality tests the probe's plumbing (patch handling,
  parsing, de-duplication, mapping), not the correctness of the oracle; and E2's mapper reads the
  same SCIP index as the gold's mapper (same-oracle circularity, [I]).
* All 20 mutations break the build: no no-break class, no multi-edit, no cascade (M0.5 limits
  carry over). Windows host, default features, one tree, one commit.
* Failure of one target blocks its dependents, so the probe shows a subset of the real
  consequences (M0.5 finding 3); a probe edge list is reported with its blocked units.
* Timings are under load (section 6), from one machine, one toolchain.
* Scratch (not committed): the worktree, target dirs, patch files, run files, load lines. Committed:
  this file, the example, `m1.3-results.md` with placeholders for paths and hashes. Public files
  carry mutation ids and aggregates only, no seed names, paths of the gold or diffs.
