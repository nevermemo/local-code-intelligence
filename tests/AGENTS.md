# Test guidance

- Shared fakes and fixtures live in `tests/support`: the fake model HTTP service (`mod.rs`) and the fake LSP (`fake_lsp.rs`, built as the `fake-lsp-server` binary from `fake_lsp_bin.rs`). Behavioral cases live in `tests/cases/*.rs`, registered as modules of the single `tests/integration.rs` binary (`child_stdin`, `config`, `evaluation`, `freshness`, `indexing`, `lsp_breaker`, `lsp_concurrent_open`, `lsp_diagnostics_wait`, `markdown_lsp`, `mcp`, `navigation`, `navigation_barrier`, `readiness`, `recipes`, `run_records`, `traverse_matrix`, `watching`). `cargo xtask test --suite <name>` filters on those module names; `recipes`, `run_records` and `traverse_matrix` have no focused suite (they are `FULL_ONLY_CASES` in `xtask/src/test.rs`, whose test fails when a new case module is in no focused suite and not on that list; use `cargo test --workspace --features local-code-intelligence/map-equivalence --test integration recipes::`, or the `Full` gate; a bare `--test integration` rebuilds the lance stack, see [testing.md](../docs/development/testing.md)).
- `tests/cases/child_stdin.rs` (suite `Lsp`) runs the LSP version probe in a re-executed child of the test whose stdin is a pipe the test holds open, against the fake server that reads stdin until EOF; a helper child that inherits the process's stdin makes it fail (N107).
- Two fake model servers exist by design: `FakeModelServer` in `lci-core` covers raw TCP connection faults, while `FakeModels` in `tests/support` covers application behavior. The C# fake-LSP config builder is `with_fake_csharp_server` in `tests/support/mod.rs` (the request timeout is a parameter); a few tests in `tests/cases/navigation.rs` still build their own `CSharpLspConfig` inline.
- The fake LSP's `--mode documents` (`with_fake_documents_server`; store and toy parser in `fake_lsp_documents.rs`) answers from the text it was sent (start-up walk, then `didOpen`/`didChange`/`didClose`/`didChangeWatchedFiles`) and records `events.jsonl` and `documents.json` in its state directory (consistent after a request round trip: never read them right after a notification without a following request); every other mode answers canned ranges.
- `tests/cases/freshness.rs` (suite `Freshness`) asks every traverse map and search channel about one edit of a mixed C#/Rust tree (the documents fake serves `lsp.*`, the SCIP file it writes lives outside the tree); `EXPECTED_GAPS` and `EXPECTED_LABELLED` (the maps `[run_profile.traverse] map_freshness` labels stale) are each asserted in both directions, so a map that becomes fresh, or whose label changes, is moved in the same commit.
- `tests/cases/traverse_matrix.rs` (a `FULL_ONLY_CASES` module; run it with `--test integration traverse_matrix::`) pins one `traverse::run` call per cell (selection notes, errors with their map lists, handle/resume, trajectory, trait seeds, `lsp.live` down and ready) on `freshness.rs`'s tree and index: response, trace and handle file against `tests/golden/traverse-matrix/<cell>.*`, with the actual text under `test-results/traverse-matrix/`. Timings, handles and the temp root are normalised, nothing else; `BLESS_GOLDEN=1` rewrites the goldens, and only the commit that changes an output (named in its message) may.
- The default run profile is one golden file, `lci-core/src/config/golden/run_profile_default.txt` (one line per `[run_profile]` leaf with its default). A slice that adds, removes or re-defaults a leaf runs the profile test with `BLESS_GOLDEN=1` (`BLESS_GOLDEN=1 cargo test -p lci-core --lib config::profile`) and reviews the golden's diff; there is no hash literal to edit.
- Tests run beside parallel builds and on a slow CI runner. A budget a test does not measure (a fake server's request timeout, a readiness probe, the cap of a wait on a real signal) is `LOADED_BUDGET_SECONDS` / `LOADED_BUDGET` from `tests/support/mod.rs`; a test whose point is a timeout keeps its short value and widens only its outer wait. Wait on the signal, never on a fixed sleep, except to show that something does not happen.
- Ports, the fakes and temporary data directories: `AGENTS.md` "Hard rules". Build and test commands, the focused suites and the `Full` gate: `AGENTS.md` "Working method" and `docs/development/testing.md`.
- Test observable contracts and recovery: parse and embedding request counts for incremental work, preserved snapshots after a failed update, fail-open paths, filtered-empty results. Do not test implementation details or documentation wording.
- A failing gate is fixed, or the change is reverted. Never weaken, delete, or `#[ignore]` a test to make a gate pass.
- Live acceptance (`cargo xtask acceptance <name>`, `cargo xtask live-acceptance`) is separate evidence. Its reports go to `test-results/` and are never committed.
